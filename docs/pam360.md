# PAM360 — integración y reporte de solicitudes de acceso

La sección **PAM360** sincroniza, vía la REST API de ManageEngine
PAM360, las solicitudes de acceso a contraseñas privilegiadas y las
muestra en "PAM360 → Solicitudes de acceso" (quién solicitó, a qué
recurso/cuenta, el motivo, la ventana pedida y el estado).

Código: `backend/src/integrations/pam360/pam360Client.js`,
`backend/src/services/pam360.service.js`.

## 1. Generar el AUTHTOKEN

PAM360 no usa usuario/contraseña para la API: se autentica con un
**AUTHTOKEN** por usuario de API, enviado en el header `AUTHTOKEN` de
cada request.

1. En PAM360, crear (o elegir) un usuario de API — *Admin → Users →
   API User Accounts* según la versión.
2. Generar/copiar su AUTHTOKEN.
3. Pegarlo en *PAM360 → Configuración* de esta app, junto con la URL
   del servidor (ej. `https://pam360.empresa.local:7272`).

El AUTHTOKEN se guarda cifrado (AES-256-GCM, igual que el resto de los
secretos de integraciones) y nunca se vuelve a mostrar completo; solo
se muestran los últimos 4 caracteres.

La cuenta de API necesita poder **ver las solicitudes de acceso a
contraseñas** (es decir, ser administrador de aprobación o tener rol
con acceso a esa lista). Si el endpoint responde vacío o con error de
permisos, revisar el rol del usuario de API en PAM360.

## 2. Certificado TLS

Si PAM360 usa un certificado autofirmado, desmarcar **"Verificar
certificado TLS"** en la configuración (activada por defecto). Sin
verificación el canal va cifrado pero no se valida a qué servidor se
conecta.

## 3. Endpoint usado

`GET /restapi/json/v1/accounts/passwordaccessrequests` ("Fetch the
List of Password Requests" en la documentación oficial de PAM360).

La respuesta trae una lista de **solicitantes**, cada uno con su
`PASSWORDREQUESTLIST`; el cliente aplana ambos niveles. Campos
usados: `REQUESTED BY`, `REQUESTED BY FULLNAME`, `PASSWD ID`,
`RESOURCE NAME`, `ACCOUNT NAME`, `REASON`, `STATUS`,
`REQUESTED TIME`, `START_TIME`, `END_TIME`.

## 4. Limitaciones conocidas

- **Inicio/Fin son la ventana solicitada, no el uso real.** El endpoint
  documentado expone `START_TIME`/`END_TIME` de lo que el usuario
  pidió al crear la solicitud; no expone cuándo hizo realmente
  checkout/checkin de la contraseña. La página lo aclara.
- **Historial acumulado.** La documentación no aclara si el endpoint
  devuelve el historial completo o solo las solicitudes abiertas. Por
  eso `pam360_access_requests` **acumula** (upsert por `PASSWD ID`, nunca
  se borra), a diferencia de "Usuarios del AD" o Veeam, que reemplazan la
  foto entera en cada sync.
- **Zona horaria.** PAM360 manda las fechas como hora LOCAL de su
  servidor, en texto y sin zona (`Dec 30, 2025 04:45 PM`), y el backend
  corre en UTC. Por eso la configuración pide la **zona horaria del
  servidor PAM360** (nombre IANA, ej. `America/La_Paz`; por defecto
  `UTC`) y las fechas se convierten a UTC al sincronizar. Si las horas
  del reporte se ven corridas, revisar ese campo y volver a
  sincronizar (las filas ya guardadas se corrigen en el siguiente sync).
